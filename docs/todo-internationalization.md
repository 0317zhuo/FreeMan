## 多页面阶段：语言路由

页面数量增长后评估 `app/[lang]`，使用 `generateStaticParams` 预生成所有支持语言与内容路径，限制未支持语言。Next.js 16 的 `params` 按当前文档异步读取。

如果采用 `/zh-CN/` 与 `/en/`，先制定 `/` 中文入口的兼容和规范地址方案；必要重定向由托管平台承担。不要在静态导出配置中添加 Next.js `i18n` 或依赖 Proxy 的自动语言协商。

仅两种语言时，优先简单的服务端字典。出现复杂复数、消息格式与大量页面后，再评估 `next-intl` 等库；实施时核查最新官方文档及静态导出要求。
