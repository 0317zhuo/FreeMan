# 找我开发业务页面结构

| 部分 | 介绍什么 | 主要目的 |
| --- | --- | --- |
| **1. 首屏介绍** | 一句话说明团队为谁解决什么问题，例如“为初创团队和成长型企业提供从产品设计到上线的定制开发”。简要列出主要服务，并放“提交需求”和“查看案例”两个入口。 | 让访客快速判断业务是否相关，并引导下一步。 |
| **2. 服务范围** | 列出可承接的工作，例如需求梳理、产品原型与 UI、网站和后台系统、移动应用、接口开发、部署上线、后续维护。说明常用技术栈，但以“能解决什么问题”为主。 | 让客户知道你能做什么，减少只看技术名词的理解负担。 |
| **3. 合作对象与项目筛选** | 说明适合合作的客户和项目类型，例如已有明确业务目标、需要定制开发、希望长期迭代的团队；同时标注最低预算、是否远程协作、不承接的项目类型等条件。 | 提前建立合作预期，过滤不匹配的询价。 |
| **4. 项目案例** | 展示代表项目，每个案例可包含客户问题、解决方案、负责范围、主要技术、项目结果。客户信息不便公开时，可匿名展示或只展示经许可的截图和数据。 | 用具体项目证明经验，而不是只用笼统宣传语。 |
| **5. 合作流程** | 按步骤介绍：提交需求 → 初步评估 → 需求梳理与报价 → 签署约定并启动 → 分阶段开发与验收 → 部署交付 → 维护迭代。每步简单说明客户需要提供什么、会得到什么。 | 让客户了解从咨询到交付的全过程。 |
| **6. 费用与付款方式** | 说明报价如何确定、是否提供付费需求梳理、付款按项目阶段还是里程碑安排、维护如何计费。可举示例，但不要在不了解需求时承诺固定总价。 | 减少客户对报价和付款的疑虑，也保护项目现金流。 |
| **7. 常见问题** | 回答客户常问的问题：没有完整需求能否咨询？设计是否包含？如何处理新增需求？代码和知识产权如何交付？是否提供维护？远程怎么沟通？项目延期如何处理？ | 在联系前消除顾虑，减少重复沟通。 |
| **8. 联系与需求提交** | 提供表单或联系方式。表单可收集项目目标、功能概述、预算范围、期望时间、联系方式，以及需求文档或原型附件。说明提交后多久会回复、后续如何安排沟通。 | 把访客转化为可评估的项目线索。 |
| **9. 页脚** | 放公司或团队名称、联系方式、社交账号、服务地区、隐私说明及必要的备案信息。 | 提供基本的信任与联系信息。 |
